JARVIS 0.7.1 — open pages in the requested browser

- Approval-gated external opening in Arc, Safari, Chrome, Brave, Edge or Firefox.
- Open an exact HTTP(S) URL or a granted local HTML file, without UI shortcuts.
- Local HTML previews include a content hash; changed files invalidate approval.
- Reject executable schemes, credential-bearing URLs and non-browser applications.
- Report macOS launch acceptance separately from verified page loading.
- External opening does not add DOM control or bypass folder grants.

The Android 0.7.0 Play Protect warning remains unresolved; no clearance is claimed
for this release. Its Google classification appeal was submitted separately.
Existing signing, private credentials, approvals and sandbox boundaries remain.

JARVIS 0.7.0 — Google account connections

- Separate Gmail and Google Calendar connections in desktop Settings.
- System-browser desktop OAuth with PKCE and a temporary local callback.
- Tokens encrypted using the existing Mac credential vault; no tokens on the phone.
- Read-only connections by default, Gmail search/plain-text reading and primary-calendar events.
- Optional email sending and event creation, each behind exact one-time action approval.
- Account changes invalidate pending actions; isolated project workers cannot access accounts.
- Connection cancellation, reconnect/disconnect controls and AI/history privacy disclosure.

Google connections require your own Desktop OAuth client, enabled APIs, browser sign-in
and consent. No Google account is bundled or connected automatically. Email/calendar
content requested in a task may enter local history and the configured AI service.
Existing-event edits/deletion, attachments and inbox/calendar monitoring are not added.
Personal OAuth Testing refresh tokens expire after seven days. Public distribution
requires a separate Google verification/privacy review. Real-account commissioning
remains a user acceptance step after installing the feature.

Source and release changes retain owner-review and exact-commit build approval.
The Mac build is locally signed, not Apple notarized; five moderate development-
packaging advisories remain under review. This is an experimental test release.

JARVIS 0.6.2 — local self-management preview

- Preserve source files under scripts/release while excluding generated output.
- Test maintenance initialization against the complete production source bundle.
- Isolated source improvement jobs followed by separate review jobs.
- Check receipts tied to the unchanged source snapshot.
- Ordinary documentation merges after review; explicit owner approval for sensitive changes.
- Source history remains separate from the installed app; local mode does not publish to GitHub.
- Signed GitHub release discovery, artifact verification and approved Mac installation.
- App identity and the fixed credential vault are checked before installation.
- Failed launch checks stop the owned new app and restore the previous app.
- Fresh-checkout runtime assets and UUID-safe dependency license packaging.
- Public source export, DMG packaging and locally signed release candidate tools.

GitHub maintenance requires separate proposer/reviewer identities and enforced owner
review and CI rules. Release publication requires a separate exact-commit owner
approval; configuration alone does not publish a release.
The current Mac build uses a local certificate, not Apple notarization. Android updates use
normal Android installation approval. Five moderate development-packaging advisories
remain under review; this is an experimental test release.
