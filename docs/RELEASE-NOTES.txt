JARVIS 0.8.3 — Mac, Windows and Android testing release

A larger update from the previous public release:
- Configurable intelligence: Codex, OpenAI-compatible servers, Ollama, Anthropic
  and Gemini task adapters, with separate tool/vision capability checks.
- Scoped skills, built-in Gmail/Calendar plugins and approval-gated custom MCP
  HTTP plugins. No external server code is silently installed or started.
- Embedded multi-tab browser with manual takeover and reviewed handover.
- Searchable settings pages, centered Voice interface and controlled subagents.
- Autopilot for trusted routine actions; consequential actions retain review.
- Native macOS accessibility interaction and reviewed window-image clicks.
- Windows11 x64 native UI Automation, local offline wake, native Codex cache
  discovery, voice and embedded browsing in a portable ZIP.

Release fixes:
- Read ordinary public search-result links without repeated approval, including
  validated DuckDuckGo result wrappers. Only observed links on the active static
  search page qualify; sensitive destinations, forms, private addresses, owner
  tabs, expired snapshots, corrections and Stop keep their existing guards.
- Bound live history and coalesce interface state delivery. Full local records
  remain retained. Approval previews are never silently shortened: oversized
  requests cannot be approved. Renderer recovery is bounded and does not replay
  tasks or actions; inspect task status before retrying.
- Skill toggles change only the enabled flag; the editor fetches full stored
  instructions separately so display summaries cannot overwrite procedures.
- Include the Windows ZIP alongside the Apple Silicon Mac DMG/ZIP and Android
  APK. Every download is bound to the source commit by signed metadata. Existing
  Mac and Android updater metadata stays compatible.

Testing limitations:
- Mac uses the owner's local signing identity; it is not Apple Developer ID
  signed or notarized. Windows has no publisher certificate. Keep platform
  security protections enabled and report installation blocks.
- Android uses the existing app signing identity. Google Play Protect classified
  an earlier APK as harmful; its appeal remains unresolved. This APK is provided
  for testing at the owner's request, not as evidence of Google's clearance.
- Windows project command execution, source maintenance/release builds,
  external-browser control and automatic updates remain unavailable.
- No universal app-control guarantee is claimed. Browser forms, account actions,
  external messages and other consequential changes still require approval.
- Voice API use has separate provider billing. Local wake uses no idle API call.
- Third-party testers configure their own credentials and remote pairing/hosting;
  owner API keys, Firebase push keys and tunnel credentials are not bundled.
- Automated checks and owner physical tests have different coverage; see
  WINDOWS.md and ASSISTANT-SETUP.md for supported capabilities and limits.
